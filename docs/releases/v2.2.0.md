# jrsctl 2.2.0

This release finishes the third field test's follow-ups and settles two long-open design questions. A hotfix now keeps the server down only for the swap itself. An import refuses a damaged archive before it touches anything. `runs list` can filter, and run ids can be shortened. The embedded documentation pages in a terminal. `init` explains itself on an install without a registered service. And jrsctl now says plainly that it manages JasperReports Server on Apache Tomcat, not from inside a container.

Download the archive for your system below, check it against its `.sha256`, and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.1.x

| What changed | What to do |
|---|---|
| **`init` and `doctor` refuse JBoss EAP, WildFly and containers** (#118, ADR-0043). `init` exits **6** when jrsctl runs inside a container (Docker, Podman or a Kubernetes pod, recognised on Linux) or when `--install-dir` names a JBoss or WildFly home. `doctor`'s new `deployment` item fails on the same conditions and, alone, exits **6**. | Nothing on a Tomcat server outside a container. For a server in a container, apply hotfixes and upgrades when building the image. REST export and import still work against it from another machine: `jrsctl init --remote <url>`. |
| **An import whose archive does not match its sidecar is refused** (#185). The first precheck compares the archive's SHA-256 with the one its `.jrsctl.json` recorded at export. On a mismatch the import stops with exit **2**, before the rollback copy and before any outage, and the plan already warns about it. | Copy the archive again, or take the export again. An archive without a sidecar is imported as before. |
| **`hotfix apply` stages its files before stopping the service** (#184). The plan now reads `stage-files` → `stop-service` → `atomic-swap`. A corrupt bundle is caught with the server still up. | Nothing. A 2.1.x run that crashed exactly between its stop and its staging can only be rolled back (`runs recover <id> --rollback`); the swap's precheck says so. |
| **`docs <name>` and `--explain` page long text in a terminal** (#187). | Press Space, Enter or `q`. Pass `--no-pager` to print everything at once. Piped output is never paged. |
| **Commands that take a run id accept part of it** (#186). A part that matches several runs exits **1** and lists them. | Scripts that pass full ids are unaffected. |

## New

- **`runs list --status`, `--operation`, `--since`** (#186). Filter by outcome (`failed`, `rolled-back`, `pending` and so on), by operation (`hotfix` covers `hotfix.apply` and `hotfix.rollback`), and by start time (a date, an instant, or an age such as `7d`). The filters apply before `--limit`.
- **Short run ids** (#186). `runs show`, `runs recover`, `runs support-bundle` and `upgrade rollback` accept the end of an id (`ab12`) or its start (`20260926-1530`). The full id is printed.
- **A pager for the embedded documentation** (#187), built on the terminal the guided menu already uses, with a new global `--no-pager` flag.
- **`doctor`'s `running-tomcat` item** (#147). It names the pid of a Tomcat running under the installation whatever `service.kind` says. It warns when the configured service disagrees: STOPPED while that Tomcat runs, or RUNNING while none does. A Tomcat started by a service jrsctl isn't configured for, or by a bare `startup` script, is at least seen.
- **`doctor`'s `deployment` item** (#118): JBoss/WildFly and containers, as above.

## Fixed

- **A hotfix's outage included copying its payload** (#184). Only the swap now runs with the server stopped, and a failed stop removes the staging tree.
- **An import never checked the checksum its export recorded** (#185). A truncated or altered archive was only noticed when the server or `js-import` failed on it, possibly inside the outage.
- **`init` on an install with no registered service** (#147) now says why it proposes `catalina` ("usual for a WAR + buildomatic install; jrsctl runs catalina.sh to stop and start Tomcat") or `manual`, and the operator guide explains how to choose a `service.kind`.
- **On Windows the process scan left out the installer's `tomcat10.exe` service** when jrsctl is not elevated. Reports now count it as a Tomcat that may be this server; the service steps are unchanged.

## Build and dependencies

- Every GitHub Action moved to its Node 24 release (GitHub removed Node 20 from hosted runners on 2026-09-16). Each pinned commit was checked against its tag.
- Maven 3.9.16 in the wrapper (SHA-256 checked against the download).
- Error Prone 2.50 with the fixes its new checks asked for; the text-block suggestion is off because it would rewrite byte-exact batch-file fixtures.
- Low-risk plugin and library updates: resources, shade, enforcer, JaCoCo, CycloneDX, versions, semver4j, jqwik.

## Documentation

- ADR-0042 (a WAR + buildomatic install uses the `catalina` kind; no separate `script` kind), ADR-0043 (Tomcat only, not in containers; answers spec §19 Q2), and ADR-0023 accepted (no full-screen terminal UI).
- The support-engineering review that spec §20 requires is recorded in `BUILD_STATUS.md` (#36).
- The operator guide, the spec and its changelog are updated for every change above.

## Known limitations

- **Windows containers** are not detected; the container check recognises Docker, Podman and Kubernetes on Linux.
- **The pager** reads single keys through the same JLine terminal as the guided menu's line editing. If it misbehaves in an unusual console, `--no-pager` prints everything at once.
- **Still open:** building from a source archive or as root (#188, details awaited from the reviewer); the live `needs-jrs` suite has no JasperReports Server image (#35); buildomatic on a real UNC share or network mount is unverified (#31).
