# jrsctl 2.3.0

**This is the final release of jrsctl.** No further fixes, security patches or support for new JasperReports Server versions will follow. What 2.3.0 supports is fixed as shipped: JasperReports Server 7.1 to 10.x on Apache Tomcat, on Windows or Linux (64-bit). The bundled Java 21 runtime will not be updated; `jrsctl --version` shows its version. To continue the work, fork the repository.

The release makes support bundles readable again when a password is a common word, and puts the vendor tools' full output into jrsctl's log. It also makes the source build work from a ZIP and as root, and records what was never verified.

Download the archive for your system below, check it against its `.sha256` and its signature (`SECURITY.md`), and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.2.x

| What changed | What to do |
|---|---|
| **A password made only of letters is masked as a whole word** (#199). A password such as `postgres` is still masked wherever it stands alone: in `user:pass@host`, `password=`, a query string, quotes, or between spaces or punctuation. It is no longer masked inside a longer name that contains it, so `org.postgresql` and `jdbc:postgresql:` stay readable. A password with any digit, symbol or space, and every encoded form of any password, is masked wherever it occurs, as before. | Nothing, unless `doctor`'s `secrets` item warns that a password equals its username or an installer default. Change that password: redaction cannot hide it, because the masked username shows it. |
| **Everything `js-export`, `js-import` and `js-ant` print goes to `logs/jrsctl.log`** (#200). Each line is redacted and tagged with the run's id, at INFO, under the logger `com.jaspersoft.jrsctl.jrs.vendor.output`. `runs support-bundle` carries it. | Expect `jrsctl.log` to grow faster during a vendor export or import; it is not rotated (see below). The failure hints for `js-export` and `js-import` now point at `jrsctl.log` and `runs support-bundle`, not at the buildomatic log, which holds only the `validate-keystore` step. |

No command, flag, exit code or configuration key changed.

## Fixed

- **A password that is a common word made support bundles unreadable** (#199). The redactor replaced it inside every word containing it. A bundle from a server on PostgreSQL with the installer's default password showed `type: [redacted]ql`, `org.[redacted]ql.util.PSQLException` and 2,796 mangled lines in `installation.log`, and the mask gave away what it hid. Checked against that server's real bundle: 0 mangled lines, and the password was still masked everywhere it stood alone. Lines stored by 2.2.0 while a run executed keep their old masking, because they are redacted when written. These are the run's own lines in `logs/jrsctl.log`, `run.json` and `transitions.jsonl`.
- **A failed vendor export or import could not be diagnosed from its support bundle** (#200). The vendor wrappers write only their `validate-keystore` step to the buildomatic log. The export or import itself printed to the console alone, and jrsctl kept only the last 20 lines. Checked live on a failing full-server export: all 1,677 lines, with the full `PSQLException` trace, reached the bundle.

## Building from source

- **A source archive builds** (#188). GitHub's "Download ZIP" or a release's source archive has no `.git`, and most unzip tools drop the executable bits. The scripts now call the Maven wrapper through `sh`, and set up the git hooks only inside a clone. `Phase0SkeletonTest` skips its git-index check when there is no `.git`. Run `bash scripts/mvn.sh verify` on Linux, or `scripts\mvn.cmd verify` on Windows.
- **Building as root on Linux works** (#188). One test that expects a permission to be refused skips when the account bypasses permission bits, which it detects by reading a mode-000 file.
- A new CI job, `archive-as-root`, builds an unpacked `git archive` ZIP as root, with unit and acceptance tests, on every push.

## Documentation

- **README and `README.txt`:** an end-of-maintenance notice.
- **New `SECURITY.md`:** vulnerability reports are no longer acted on. It shows how to check a release's checksum and verify its signature with OpenSSL against the publisher key (Ed25519, fingerprint `245731f29b662027`).
- **`CONTRIBUTING.md`:** how to build from a clone, a ZIP or as root, and the checklist for closing the project down after this release.
- **`BUILD_STATUS.md`:** up to date for 2.x, with what stays open at the end of maintenance.
- **Operator guide, spec §5.8 and §12.4, and the spec changelog:** updated for #199 and #200.
- **Closed without further work:** #31 (buildomatic on a network share) and #35 (a live test suite against a JasperReports Server image). Their closing comments record what was and was not verified.

## Known limitations

These stay as they are; there will be no later release to change them.

- **Paths verified only against fake vendor scripts, never against a live installation:**
  - `upgrade --export` and `upgrade --test`;
  - `upgrade rollback --restore-database`;
  - the key alias reaching the vendor import;
  - the vendor strategy's rollback of new content;
  - the Linux service paths;
  - an official hotfix package from support (checked against the documented layout only).

  Try an upgrade on a copy of the server first.
- **Buildomatic on a network share** (#31):
  - Verified: `doctor` and `init` through UNC paths, mapped drives and a Linux gvfs mount, and a vendor export from a mapped share.
  - Not verified: a vendor import or an upgrade with the tree on a share, and a kernel CIFS or NFS mount.
  - A raw UNC path does not work for the vendor tools; use a mapped drive letter.
- **The adapter was never tested against a live server of any version other than 10.0.0 PRO** (#35). The other rows of the compatibility matrix are covered by recordings synthesised from their `serverInfo` fixtures.
- **Windows containers are not detected.** The container check recognises Docker, Podman and Kubernetes on Linux.
- **`logs/jrsctl.log` is not rotated.** Delete or archive it by hand when it grows; `runs support-bundle` reads only the run's own lines and the last 200.
- **The pager** reads single keys through the guided menu's JLine terminal. If it misbehaves in an unusual console, `--no-pager` prints everything at once.
